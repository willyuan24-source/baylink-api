# Member profiles and direct messages — September 9, 2026

## Public profiles

`PATCH /api/users/me` accepts `profileTheme` (`bay`, `sunset`, `redwood`, `lavender`), `statusText` (a trimmed string up to 60 UTF-16 units), and `coverImage`. Older profiles default to `bay`, an empty signature, and no cover.

Both `avatar` and `coverImage` accept a PNG, JPEG, WebP, or GIF base64 data URL of at most 4 MiB decoded bytes. The API checks the declared type, canonical base64 encoding, size, and raster file signature before upload. SVG and arbitrary remote URLs are rejected. An existing URL belonging to the current user's corresponding image field may pass through unchanged. An empty string removes the image. Upload failure returns 502 and does not persist the partially edited profile.

Public profile endpoints use an explicit field allowlist. Conversations expose only the other member's ID, nickname, avatar, verification flags, administrator flag, city, profile theme, and signature. Public post previews retain images, city, type, budget, and dates, with no contact preference or private contact values.

## Quoted replies

`POST /api/conversations/:id/messages` accepts optional `replyToId` for a text message. It must identify an existing text message in the same conversation. Contact cards, legacy contact-share messages, foreign messages, and client-provided `replyTo` objects are never used as quote sources.

Returned `replyTo` is `{ id, senderId, content }`, generated by the API from the stored source. Content is a whitespace-normalized preview of up to 160 Unicode code points, with an ellipsis when shortened.

New message and conversation external IDs use UUIDs; existing IDs remain valid.

## Reactions

`PUT /api/conversations/:id/messages/:messageId/reaction` accepts `{ "emoji": "👍" }`. Supported values are `👍`, `❤️`, `😂`, `🎉`, `🙏`, `👀`; `null` removes the caller's reaction.

Each user has one reaction per message. An atomic `$set` or `$unset` affects a server-derived SHA-256 user key inside the stored vote map, so simultaneous members cannot overwrite each other's votes. Repeating the same setting does not duplicate a reaction. The response contains the updated public message:

```json
{
  "reactions": [{ "emoji": "👍", "userIds": ["member-id"] }],
  "reactionVersion": 3
}
```

`reactionVersion` increments atomically. Clients should discard older reaction versions when merging out-of-order HTTP or Socket.IO results. `message_updated` carries the same public message to verified conversation members only. Reactions require an active session, conversation membership, a messaging-enabled sender account, an available recipient, no block in either direction, and a limit of 60 requests per user per minute.

## Private unread state

`GET /api/conversations` and `POST /api/conversations/open-or-create` include `unreadCount` for the caller. Fetching a conversation's messages does not mark it read.

Use `POST /api/conversations/:id/read` with the **actual observed message IDs**, in batches of at most 500:

```json
{
  "messageId": "last-observed-id",
  "messageIds": ["first-observed-id", "last-observed-id"]
}
```

`messageId` must be the final element of `messageIds`. When `messageIds` is omitted, only that single `messageId` is marked. The API validates every ID against the same conversation, freezes the corresponding internal Mongo IDs, and atomically adds only the caller to each selected message's private `readBy` set. Unknown or foreign IDs reject the request without changing unread state. Sending an older read request cannot undo a newer read. Messages arriving during the request remain unread even if their timestamps or Mongo IDs sort before the submitted boundary; neither timestamp nor ObjectId is treated as proof that a message was seen.

The response is `{ conversationId, unreadCount }`. No read receipt or counterpart read state is published. Message GET remains an array, ordered by `createdAt` then Mongo ID; response and socket payloads exclude `readBy` and the internal vote map. Older messages without read state initially count as unread until the user views and acknowledges them.

## Validation

`npm run check` and `npm test` passed: 73 tests, including nine new profile and messaging cases. New cases exercise malformed/oversized image rejection, upload failure preservation, public field privacy, same-conversation quote validation, contact-card exclusion, concurrent independent reactions, exact-session socket authorization, blocks/account limits/rate limits, and a same-millisecond late-arrival race with an earlier Mongo ID. Tests use isolated memory models and real HTTP/Socket.IO sessions; no production account or user message is modified.
