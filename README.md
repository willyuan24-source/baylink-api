# BAYLINK API

Run `npm test` for isolated HTTP, Socket.IO, security, search and AI behavior tests. Tests use in-memory models and block `.env` loading, MongoDB connections and external AI requests. Run `npm run check` for the server syntax check.

## Search and BayBay

- `GET /api/posts?keyword=...` uses literal matching with AND between up to 8 terms. Explicit synonyms include 租房/租屋/出租 and 二手/闲置; region terms also match their known cities. Category, visibility, author blocks and pagination are applied before results are returned.
- `POST /api/ai/guide-chat` accepts `{message, context?: {categoryHint, currentPath}}`. Clear requests for listings use a read-only provider search without an AI call. It scans up to the newest 200 candidates after category, location, room-type and public-visibility filters, returning at most 3 cards. Signed-in users' author blocks apply; administrators cannot obtain hidden posts through BayBay.
- `matchingPosts` contains only `id`, `title`, `city`, `budget`, `confirmedAt?`, `createdAt`, `status?`, `category`. Contact and author records are not returned or sent to the model. Contact-like text in card labels is redacted.
- Monthly budget comparisons require a clear upper limit and monthly unit in the question. A listing must have a single unambiguous monthly amount in its budget, or the same bare amount explicitly described as monthly rent in its title/body. Daily/weekly prices, ranges, starting prices, per-person amounts and unclear currency/units are not treated as a confirmed monthly price. Original posts are never rewritten by this search.
- `matchNote` explains recognized constraints and uncertainty; `responseMode` is `search`, `ai` or `fallback`. `degraded: true` means AI or retrieval failed/unavailable and the response is basic guidance, not completed search results. Active status alone is not proof of current availability.
- Knowledge questions receive relevant excerpts and source links from `data/guide-catalog.json`, generated from the frontend's guide data with `scripts/export-guide-catalog.ts`. Regenerate and copy this catalog whenever guide content changes. The server does not browse source sites or claim live policy verification.
- Draft model requests have a 12-second request/body timeout; guide answers allow 20 seconds for complete multistep output. Guide responses use plain-text numbered paragraphs, up to 1,200 characters and a 2,000-token output budget. The server accepts only completed (`finish_reason: stop`) model output; unfinished or oversized answers degrade instead of being sliced mid-sentence. Existing per-IP quotas remain in place. Test-only fixture providers may be injected through `createApplication({ai: {guideChat, postAssist}})`; test mode otherwise refuses external AI calls.

## Planner discovery and explicit web lookup

- `POST /api/planner/recommend` still returns the existing event `suggestions` schema. It additionally returns `placeSuggestions: [{id, placeId, date, reason, reasons, unknowns, budgetStatus}]`, at most three published places. `excludePlaceIds` accepts up to 100 canonical IDs independently of the existing event exclusion list. Known opening dates, current closed-day schedules, geography, age limits, setting and admission constraints are enforced before AI ranking. Named venues and Chinese/English place categories are matched against the catalog; explicit place requests do not get unrelated events to fill the list. Unknown hours and meal/shopping amounts stay unverified. AI may rank only the actual bounded candidates supplied to it; its invented or ineligible IDs are discarded.
- `POST /api/planner/web-search` is a separate, explicitly clicked lookup. Accepts only `{query, locale?, date?, region?, city?}`: query 2–500 characters, locale `zh-Hans|zh-Hant|en`, valid ISO day, existing region ID, and city up to 80 characters. Omit empty optional fields. Private plans, account IDs, messages/history and arbitrary nested filters are rejected. No background search or public-catalog mutation occurs. The provider receives only this public query/context, never saved plans.
- Success is `{ok:true,responseMode:'web',checkedAt,answer,sources:[{title,url}],cached}`. Source entries come from actual Responses `url_citation` annotations following a completed web tool call; no generated source snippets are used. `answer` uses `[1]`, `[2]` markers referencing this source list. **Render those markers as visible clickable citations** and label web information as needing confirmation. Sources must be HTTP(S) URLs without credentials, unusual ports, literal IPs or local hostnames; DNS must resolve exclusively to public addresses. The server never fetches citation pages itself. Source validation is point-in-time and cannot guarantee later redirects or changes.
- Success may additionally contain `candidates: [{id,name,city,summary,timeSummary,priceSummary,sourceUrls}]`, maximum five private-discovery place cards. All fields except `id`, `name` and `sourceUrls` are nullable. Each non-null fact must have its own actual safe citation in the same response; a typed URL or invented `[1]` is insufficient. IDs are stable hashes of the cited place identity. The same single provider call emits a bounded `BAYLINK_CANDIDATES_V1` JSON block after the cited answer, which the server removes from the visible answer and validates; ordinary prose is never mined for candidate names. Malformed or absent blocks yield no cards while preserving a usable cited answer. Summaries are model paraphrases, not source excerpts or independent verification. No address, coordinates, machine-readable hours, numeric admission values or automatic public-catalog writes are added. Render each card's `sourceUrls` as visible links; retain the existing date reminder and treat `checkedAt` only as retrieval time. A cited weekly schedule is not confirmation of the selected date, and a price summary must not be interpreted as a complete outing budget.
- [Official OpenAI web-search documentation](https://developers.openai.com/api/docs/guides/tools-web-search) establishes the Responses `web_search` tool and citation annotations. Requests use `https://api.openai.com/v1/responses`, `store:false`, required search, low context, 1,800 output tokens and `max_tool_calls:1` ([Responses reference](https://developers.openai.com/api/reference/cli/resources/responses/methods/create)). Default `gpt-4.1-mini` is independently configurable with `OPENAI_WEB_SEARCH_MODEL`; it does not inherit the older chat model setting. Account access and billing are not verified by local tests.
- Missing credentials, disabled search, incomplete/uncited output, unsafe-only sources and provider failures return `503 {ok:false,error}` without fake results. Invalid requests return 400; exceeded quotas return 429. Calls have a 20-second timeout. Per-IP limits are 5/minute and 20/rolling day, plus three concurrent calls per process. Each attempted provider call consumes a shared atomic MongoDB `PostTranslationQuota` bucket named `planner-web-search:UTC-date`, default 100/day across replicas/restarts; failures count too. If quota storage is unavailable, no provider call is made. Successful results are cached for 600 seconds by query/context hash, maximum 200 entries per process; same-query in-flight calls are deduplicated and failures cool down for 30 seconds. Cache hits cost no provider quota. No query text or IP is added to application logs or stored in the quota collection.
- Product metrics add `planner_outing_adopted`, `planner_edit_applied`, `planner_web_search` to the existing day/event/locale counters. The client sends the web-search metric only after success; the search route does not double-count it. Extra identity, query, plan and source fields are rejected. Tests inject `ai.plannerWebSearch` and `plannerWebLookup`; test mode blocks real providers by default. The local suite validates provider payloads, citations, URL/DNS checks, limits, cache, timeout and compatibility without a paid API call.

## Public post translations

- `POST /api/posts/:id/translation` accepts only `{target: 'en'}`. It reads the published post from the database and returns `{ok, target, source, translation}`; both text objects contain exactly `title`, `description`, `budget`, and `timeInfo`. English-only posts return the original fields without an AI call. Original posts are never rewritten.
- Only publicly visible posts are eligible, including when the caller is an administrator. Deleted/hidden posts and signed-in viewers' block relationships return 404. Visibility, blocks and source content are checked again after a translation finishes. Contact preferences, private messages, comments and account details are not sent to the provider.
- Successful translations are cached in MongoDB by source-content hash, target and prompt version, with a 180-day TTL. Edits invalidate the hash without relying on `updatedAt`. Every cache lookup still requires current public access. Same-content generation is deduplicated within a process, and failed generations receive a 60-second cooldown.
- New provider calls are limited to 20 per IP per minute, three concurrent calls per process, and 300 calls per UTC day across instances/restarts using an atomic MongoDB quota. All translation requests, including cache hits, are limited to 120 per IP per minute. Optional environment settings are in `.env.example`. Cached results remain usable when the provider is unavailable or the daily budget is reached.
- Translation uses `OPENAI_TRANSLATION_MODEL`, falling back to `OPENAI_MODEL`, then `gpt-4o-mini`, with a 20-second timeout. Only completed JSON responses with the four bounded string fields are accepted. The validator preserves numeric strings, currency symbols, percentages, URLs and email addresses; unexpected output falls back to the original text in the frontend. Per the [OpenAI Chat Completions reference](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create), requests use `max_completion_tokens`; GPT-5/o-series models use low reasoning without a temperature override. `json_object` is paired with application-level validation.
- `tests/post-translation.test.js` covers access checks, edit/moderation races, persistence, limits, provider payloads and failures using fake providers only. Inject `createApplication({ai: {postTranslation}})` for isolated route tests; test mode otherwise refuses external AI requests.
